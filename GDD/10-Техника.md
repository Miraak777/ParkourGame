# Техника

## Структура проекта

```
res://
├── player/            # player.tscn (CharacterBody3D) + states/
├── world/
│   ├── kit/           # модульные ассеты завода
│   ├── hazards/       # базовые классы опасностей
│   └── machines/      # движущиеся элементы
├── levels/
├── resources/         # .tres: параметры движения, опасностей, зон
└── autoload/          # Settings, GameState, Audio
```

## Ключевые решения

- Игрок — `CharacterBody3D` + машина состояний (см. раздел «Контроллер-движения» ниже)
- Все параметры движения/опасностей — `Resource` (.tres): крутятся без кода
- Опасности — базовый класс `Hazard3D`: сигналы `telegraph_started`, `kill`, `push`
- Машины управляются по «фазовому» API: `get_phase()`, сигнал `phase_changed` — уровни слушают фазы, а не тикают сами
- Чекпоинты — нода-маркер + сигнал в GameState

## Движущиеся платформы (важно!)

- Наследовать скорость платформы в прыжке: `get_platform_velocity()`
- Плавность: физическая интерполяция (Godot 4.4+) или свой сглаживатель
- Тест-сцена «игрок на лифте» на отсутствие дрожи — с первого дня проекта

## Пайплайн уровней

- Уровни собираются из кит-модулей; логика — нодами-маркерами
- Тестовая арена: полоса разгона, стена для wallrun, пресс-мишень

## Контроллер-движения

### Машина состояний

Ground ↔ Air ↔ Slide → Wallrun → Walljump → Mantle → Ledge → Climb → Vault

Каждое состояние — класс/сцена, параметры берёт из Resource.

### Каркас

- `move_and_slide()` каждый физический кадр; состояние меняет accel / friction / gravity_mult
- Таймеры coyote и jump buffer живут в базовом состоянии (значения — [[06-Параметры]])
- Контекстный вход: raycast/сферы для ledge/vault/wall; выбор действия по геометрии

### Параметры (Resource «MovementSettings»)

| Группа | Параметры |
| --- | --- |
| Ground | base_speed, sprint_mult, accel, friction |
| Air | air_control, gravity, fall_gravity_mult, max_fall_speed |
| Jump | height, forward_inherit |
| Slide | min_entry_speed, slope_boost, friction |
| Wallrun | duration, gravity_mult, walljump_force, lean_angle |

### Контракт импульса

- Единый вектор скорости живёт между состояниями; состояния только модифицируют
- **Ни одно состояние не сбрасывает горизонтальную скорость в ноль**

## Производительность

### Цель

Целевой FPS на минимальном ПК — [[06-Параметры]]; сам минимальный ПК уточнить в [[00-Главная]].

### Инструменты Godot 4

- `MultiMeshInstance3D` для повторяющихся деталей (трубы, балки)
- Occlusion culling для интерьеров; LOD для больших залов
- Свет: подход не решён — арт-решение открыто в [[Арт-стиль]]. Здесь зафиксированы только техтребования: смешанный свет (LightmapGI + немного realtime), механизмы как источники света

### Правила

- Механизмы двигаются трансформами/анимацией, не физикой (кроме прямых взаимодействий)
- Далёкое от игрока движение — упрощать/замирать (LOD логики)
- Плавность платформ — в приоритете

Язык: русский. Это дизайн-документ, не код.

## Что где лежит

- `GDD/` — каноничный дизайн-документ. Разложен по разделам гайда `GDD/Правила тех ДД.md`. Плюс `99-Шаблоны`.
- `GDD/00-Главная.md` — точка входа: карта разделов, конвенции, паспорт проекта.
- `GDD/Правила тех ДД.md` — гайд, по которому устроен GDD. Источник истины по структуре: [Правила тех ДД](GDD/Правила%20тех%20ДД.md).
- `GDD/Журнал-решений.md` — почему что менялось.
- `README.md` (в корне) — визитка игры для внешних: страница Steam, питч-док, разговор с издателем. Собрана на основе GDD, но это отдельный документ со своим форматом: каноничных формулировций не обязана повторять, а правил ведения GDD не наследует. Канон — в `GDD/`.

## Структура разделов

- Раздел с **одной** заметкой — это сама заметка с префиксом номера раздела: `06-Параметры.md`. Папку не заводим.
- Раздел с **несколькими** заметками — папка с префиксом номера: `07-Дизайн/`. Имена заметок внутри — без префикса.
- Префикс с номером есть у любого раздела независимо от вида — он задаёт порядок и принадлежность.
- Если в разделе становится вторая заметка — разворачиваем папку, первую заметку переносим внутрь и убираем у неё префикс.
- Служебные файлы (карта, журнал, майлстоуны) — без номера раздела, в корне `GDD/`.

## Навигация

- Связи — вики-ссылки `[[...]]`; имена файлов = имена ссылок
- Шаблоны новых заметок: `GDD/99-Шаблоны/`
- Папку `.obsidian/` не трогать

## Где живут служебные пояснения

Читательские заметки не содержат служебных пояснений: «это не часть GDD», «это визитка», «здесь канон», «см. правила ведения». Такие вещи — информация для агентов, и им место здесь, в `AGENTS.md`. В заметках — только содержание, которое нужно читателю: описание игры, правила, цифры, вопросы.

Исключение — `GDD/00-Главная.md`: это техкарта набора, её назначение и есть служебная информация.

## Конвенции GDD

- Frontmatter: только `tags`. Статуса заметки нет — он не несёт смысла
- Вопросы и прочие колауты — в конце заметки, без отдельного заголовка под них
- Зрелость идеи помечается эмодзи прямо в тексте: 🔴 идея · 🟡 черновик · 🟢 готово
- Теги: один тег раздела + ноль-один вспомогательный; состав — в `GDD/00-Главная.md`
- Заметки разделов 05-10 несут ещё тег состояния: `#не_утверждено`, `#на_проверку` или `#утверждено`
- Теги логики (`#система_`, `#механика_`, `#элемент_`) — отдельный слой, словарь в `GDD/03-Термины.md`
- Паспорт проекта (`GDD/00-Главная.md`): жанр, движок, героиня, сеттинг, целевая аудитория, платформы, управление. Техническая информация в паспорт не пишется

## Выселение

Если пользователь просит что-то выселить, вынести, перенести или убрать из заметки:

- ищем этому новое место в существующих разделах;
- если места нет — делаем новую заметку в подходящем разделе;
- если новая заметка не подходит ни в один из разделов — сообщаем пользователю и ждём указаний, куда её положить;
- освободившееся место не заполняем выдуманным содержанием: остаётся заготовка или раздел сокращается.

## Числа

- Все точные числовые значения живут только в `GDD/06-Параметры/Параметры.md`
- В остальных заметках на месте числа — ссылка на конкретный параметр: `[[Параметры#coyote_time]]`
- Новое число сначала вписывается в реестр, затем используется в тексте
- Значение, вписанное в обход реестра, считается ошибкой оформления

## Протокол правок

- Ответ на открытый вопрос: перенести в основной текст, колаут удалить
- Ничего не удаляется по-настоящему: снятое помечаем, а не выкидываем; причина — в `GDD/Журнал-решений.md`
- Не выдумывать решения: нет данных — спроси или пометь «предположение»
- Новые механики — по `Шаблон-механики`, новые системы — по `Шаблон-системы`
- Разделы без содержимого не удаляем: оставляем заготовку с планом, что там будет

## Git

- Git можно использовать для проверки состояния: `git status`, `git diff`, `git log`, `git show` — свободно.
- Запрещено без явного указания пользователя: `git add`, `git commit`, `git push`, `git reset`, `git restore`, `git clean`, `git rebase`, удаление веток и тегов.
- Нужно закоммитить — готовим сообщение в формате ниже и отдаём его пользователю, коммит не делаем.
- Индекс (`git add`) тоже не трогаем: он меняет то, что попадёт в коммит, а это решение пользователя.
- Сообщения коммитов **не предлагаем заранее** — только если пользователь сам их запросил.
